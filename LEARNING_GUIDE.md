# Как разрабатывать и учиться

## Исходный уровень

Пользователь профессионально знает React и TypeScript: компоненты, типы, состояние и обычные инструменты фронтенда не нужно объяснять с нуля. При этом он новичок в геймдеве. Не предполагать знакомство с игровым циклом, координатными системами, векторами, коллизиями, конечными автоматами, IK или балансом боя.

## Формат работы агента

1. Назвать одну ближайшую цель и наблюдаемый результат.
2. Объяснить новое игровое понятие: что это, зачем сейчас нужно, как оно влияет на поведение.
3. Обозначить небольшой объём изменения. Не реализовывать следующий этап попутно.
4. Сделать целостное небольшое изменение без временных костылей.
5. Проверить сборку и, когда появились правила, подходящее поведение.
6. Дать короткую ручную проверку: действие пользователя → ожидаемый результат.
7. Объяснить причинно-следственную связь и разумные компромиссы. Отдельно назвать, что ещё не реализовано.

Не вываливать сотни строк без объяснения. Не заставлять пользователя подтверждать каждую техническую мелочь: выбирать разумные обратимые дефолты в рамках текущей задачи. Спрашивать, когда выбор существенно меняет игру. Не превращать обучение в лекцию до первого проверяемого результата.

## Понятия в порядке появления

| Понятие | Что объяснить | Небольшая проверка в будущем |
| --- | --- | --- |
| Игровой цикл | Браузер даёт кадры разной длины; правила обновляются отдельно от рисования | Изменение частоты кадров не должно менять скорость обычного движения |
| Фиксированный шаг | Накопитель времени вызывает правила порциями по 1/60 секунды | Одинаковые команды на одинаковых шагах дают одинаковое состояние при отсутствии случайности |
| Вектор и нормализация | Направление и длина движения; почему диагональ без нормализации быстрее | Сравнить путь прямо и по диагонали |
| Локальные координаты | Лево бойца отличается от лева экрана | Повернуть бойца и проверить стороны |
| Команда и снимок | Ввод сообщает намерение; симуляция решает результат; рендер читает данные | Вызвать движение без Phaser в проверке симуляции |
| Конечный автомат | Фазы ограничивают допустимые переходы и действия | Во время восстановления нельзя начать новую атаку |
| Коллизия и sweep | Между кадрами клинок может пересечь цель, не оказавшись внутри неё в конце | Проверить быстрый удар и край дальности |
| Интерполяция | Рендер может сглаживать переходы между рассчитанными состояниями | Сравнить движение при низкой частоте симуляции |
| IK | Целевая точка кисти определяет положение локтя при фиксированных длинах костей | Перемещать хват, проверять достижимость и отсутствие скачков |
| Телеграфирование | Игроку нужно время увидеть намерение до последствий | Прочитать сектор и замах AI до попадания |
| Баланс | Времена, расстояния и цены создают выбор, а не просто набор чисел | Изменить один параметр и объяснить изменение тактики |

Аналогии с React допустимы, но игровой update не является React render. Не нужно переносить состояние каждого кадра в React или строить игровой мир как дерево DOM-компонентов.

## Правила качества

Отделять «не реализовано» от «временно обходим». Маленькое решение может быть простым и архитектурно корректным. Не нужны заранее универсальный движок, ECS, сложная шина событий или абстракции под воображаемые функции.

Фиксированный шаг сам по себе не гарантирует воспроизводимость: важны одинаковые команды, порядок обновления и контролируемая случайность. Readonly в TypeScript сам по себе не делает вложенные объекты неизменяемыми во время выполнения.
