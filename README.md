# By One''s Hand

Минимальный стартовый проект **Phaser 3 + TypeScript + Vite**. Игровые механики не реализованы. При запуске виден пустой тёмный холст — это ожидаемый результат.

## Запуск

Нужен Node.js 22.12+ (подойдёт Node 22 LTS).

```powershell
cd C:\_DATA\projects\by-ones-hand
npm install
npm run dev
```

Открой адрес, который напечатает Vite (обычно http://127.0.0.1:5173).
После появления package-lock.json для повторяемой установки используй `npm ci`.

```powershell
npm run typecheck
npm run build
npm run preview
```

`build` проверяет TypeScript и создаёт папку dist. `preview` показывает собранную версию через локальный HTTP-сервер. Не открывай index.html напрямую с диска.

## Структура

```text
src/
  simulation/Simulation.ts   Независимое состояние и шаг симуляции
  app/SimulationRunner.ts    Накопитель времени, фиксированный шаг 60 Гц
  render/StarterScene.ts     Пустая сцена Phaser, получает снимок состояния
  main.ts                   Создание и связывание слоёв
  style.css                 Полноэкранный холст
```

Поток: `Phaser update (мс) → адаптер времени (сек) → Simulation.step → readonly snapshot → сцена`.
Симуляция не зависит от Phaser; Phaser может читать её снимки. Сцена получает функцию через конструктор, поэтому не создаёт симуляцию сама. Физика Phaser намеренно не подключена.

Сейчас симуляция хранит только номер шага и прошедшее время: это демонстрация границы, а не игровая система. Снимок — новый объект с примитивными полями, поэтому визуальный слой не получает ссылку на изменяемое состояние.

## Первые понятия

**Игровой цикл** вызывает обновление каждый кадр. В отличие от React, это непрерывная работа даже без пользовательских событий.

**Симуляция** отвечает за то, что произошло; **рендер** — за то, как это показано. Изменение цвета будущего персонажа не должно менять правила игры.

**Фиксированный шаг** обновляет правила порциями по 1/60 секунды независимо от частоты монитора. Накопитель хранит остаток времени между кадрами. Для длинных кадров учитываются максимум 0.1 секунды, поэтому после зависания приложение не пытается просчитать огромную очередь шагов. Это сознательно замедляет игровое время относительно реального при зависаниях.

**Снимок состояния** — данные для отображения. TypeScript readonly проверяет контракт при разработке; для будущих вложенных объектов нужно сохранять отсутствие общих изменяемых ссылок.

Интерполяция между снимками пока не нужна: отображаемых движущихся объектов нет. Добавлять её следует вместе с первым движением, если возникнет визуальная необходимость.
