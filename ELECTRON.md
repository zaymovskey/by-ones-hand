# Electron: запуск и сохранения

## Три части приложения

**Main** (`electron/main.ts`) — процесс Node.js, который создаёт окно Electron, управляет жизненным циклом приложения и имеет доступ к диску. Здесь зарегистрированы обработчики IPC. `electron/save-store.ts` отвечает за JSON-файлы.

**Renderer** (`src/`) — веб-страница внутри окна Electron. Здесь остаются Phaser, адаптер времени и независимая игровая симуляция. Electron не меняет игровой цикл. У renderer нет доступа к Node.js, fs или произвольным файлам.

**Preload** (`electron/preload.ts`) — небольшой мост, который выполняется перед страницей в изолированном контексте. Через contextBridge он предоставляет только `window.saves.read(slot)` и `window.saves.write(slot, document)`. Общий контракт находится в `shared/saves.ts`; тип Window — в `src/desktop.d.ts`.

Поток сохранения: renderer → preload → IPC → main → файл. Ответ возвращается Promise. Это похоже на обращение к асинхронному сервису, но сообщения идут между процессами одного приложения, а не на HTTP-сервер.

## Команды

```powershell
npm ci
npm run dev
```

`electron-vite` собирает main и preload, поднимает внутренний Vite dev server для обновления renderer и запускает окно Electron. Внешний браузер не открывается. Это инструмент разработки, отдельного серверного приложения нет. Для завершения закрой окно или нажми Ctrl+C в терминале.

```powershell
npm run build
npm run preview
```

Production-файлы находятся в `out/main`, `out/preload`, `out/renderer`. Preview запускает Electron с локальным собранным HTML, без dev server.

```powershell
npm run pack
npm run dist
```

`pack` создаёт приложение без установщика в `release/win-unpacked`. `dist` создаёт Windows NSIS-установщик в `release`. Подпись сертификатом не настроена; для публичного распространения её можно добавить отдельно. Сборка через electron-builder может скачивать вспомогательные инструменты.

## Где лежат данные

Путь определяется только в main: `path.join(app.getPath('userData'), 'saves')`. На Windows обычно это `%APPDATA%\by-ones-hand\saves` при разработке, а у упакованного приложения имя каталога может соответствовать productName. Точный путь можно увидеть в DevTools main-процесса либо проверить каталоги в `%APPDATA%`. Данные не записываются рядом с exe, в src или в архив приложения.

Слот `manual-check` соответствует `manual-check.json`. Имена: 1–48 символов, строчные латинские буквы, цифры, `_`, `-`; первый символ — буква или цифра. Произвольные пути запрещены. Формат документа: `{version: 1, data: ...}`. Data содержит только JSON-значения. Максимальный размер файла — 1 MiB, глубина data — 64. Несуществующий слот возвращает null; повреждённый JSON, неизвестная версия и ошибки диска отклоняют Promise, их нужно обрабатывать в будущем интерфейсе сохранений.

Записи выполняются последовательно через временный файл в той же папке и переименование. Это защищает от частичной обычной записи, но не является гарантией сохранности при физическом отказе диска. Проверка версии пока проверяет оболочку документа; игровую схему и миграции нужно добавить, когда появится реальное состояние игры.

## Ручная проверка без изменения игры

Запусти приложение и открой DevTools окна сочетанием Ctrl+Shift+I. В Console выполни:

```js
await window.saves.write('manual-check', {
  version: 1,
  data: { message: 'Проверка сохранения', counter: 1 }
});
await window.saves.read('manual-check');
```

Должен вернуться записанный объект. В подпапке saves появится читаемый JSON-файл. Закрой и снова запусти приложение; повторное чтение должно вернуть тот же объект. Для проверки отсутствующего файла: `await window.saves.read('missing-slot')` вернёт null. Попытка записи в `../outside` должна завершиться ошибкой.

`typeof require` в renderer должен вернуть `undefined`. Игра по-прежнему показывает пустой тёмный холст.

## Автоматическая проверка

`npm run test:electron` собирает production и запускает настоящий Electron с временным userData. Проверяет Phaser canvas, настройки изоляции, отсутствие require, preload/IPC, запись/чтение/перезапись, сохранение после перезагрузки страницы, запрет некорректного имени/версии/размера и IPC из постороннего окна. Тестовые файлы удаляются, пользовательские сохранения не затрагиваются.

## Границы безопасности

Включены contextIsolation и sandbox, отключён nodeIntegration. Preload не раскрывает ipcRenderer или произвольные каналы. Main проверяет окно, главный frame и точный URL отправителя каждого запроса. Новые окна, переходы со страницы и разрешения браузера запрещены. CSP ограничивает выполнение скриптов и встраивание контента. Development WebSocket разрешён для Vite HMR. Симуляция не импортирует Electron и не работает с диском; сохранение будущего состояния подключается через отдельный прикладной адаптер.
